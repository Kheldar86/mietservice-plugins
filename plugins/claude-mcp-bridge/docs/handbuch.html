1. Überblick

Die Claude MCP Bridge macht diese WordPress-Website zu einem Connector für Claude – im Browser, in der Desktop-App und in der Claude-App auf dem Handy. Claude kann Inhalte lesen und Änderungen vorschlagen. Ausgeführt wird jede Änderung erst, wenn du sie hier im WordPress-Backend freigibst.

  • Lesen geht sofort (Beiträge, Seiten, Medien, Kommentare; im Expertenmodus auch Dateien, Datenbank, WP-CLI).
  • Ändern erzeugt immer einen Vorschlag mit Freigabe-Link. Du siehst genau, was passiert (Vorher/Nachher, Code, SQL, Befehl) und entscheidest.
  • Riskante Aktionen verlangen zusätzlich dein WordPress-Passwort – oder, wenn eingestellt, nur den Zwei-Faktor-Code aus Aegis.

2. Einrichtung

Voraussetzungen

  • HTTPS auf der Website
  • Permalinks nicht auf „Einfach“ (Einstellungen → Permalinks)
  • Ein Administrator-Konto

Verbinden (einmalig)

  1. Claude MCP → Einstellungen: „Bridge aktiv“ anhaken und speichern.
  2. Kopplung starten (15 Min.) klicken. Das Fenster schließt automatisch nach der ersten Registrierung.
  3. In Claude (am einfachsten auf claude.ai im Browser): Einstellungen → Connectors → Benutzerdefinierten Connector hinzufügen. Als URL die Connector-URL von der Einstellungsseite einfügen.
  4. Auf Verbinden tippen, bei WordPress anmelden, auf der Zustimmungsseite prüfen, dass die Weiterleitung an claude.ai geht, und Erlauben wählen.

Der Connector steht danach automatisch auch in der Handy-App zur Verfügung.

Alternative: eigener OAuth-Client

Statt Kopplungsfenster kannst du auf der Einstellungsseite einen Client mit Secret erzeugen und Client-ID/Secret in Claude unter Erweiterte Einstellungen des Connectors eintragen. Das Secret wird nur einmal angezeigt.

3. Mit Claude arbeiten

Schreib Claude einfach, was du möchtest. Beispiele:

  • „Welche Entwürfe habe ich gerade?“
  • „Schreib einen Blogbeitrag über Fahrradanhänger für Familien und leg ihn als Entwurf an.“
  • „Ergänze bei allen Bildern ohne Alt-Text einen passenden Alt-Text.“
  • „Welche Kommentare warten auf Freigabe? Markier offensichtlichen Spam.“
  • Expertenmodus: „Warum ist die Startseite langsam? Schau dir die aktiven Plugins und die Cron-Jobs an.“ · „Ändere im Child-Theme die Linkfarbe auf Dunkelgrün.“ · „Ersetze in der Datenbank alle http://-Links durch https:// – erst als Probelauf.“

Für jede Änderung antwortet Claude mit einem Freigabe-Link. Claude darf erst behaupten, dass etwas erledigt ist, wenn der Status „ausgeführt“ ist.

4. Freigaben

Offene Vorschläge findest du über den Link von Claude oder unter Claude MCP → Freigaben (mit Zähler im Menü). Jede Freigabeseite zeigt:

  • Risikostufe: normal (Inhalte), hoch (Dateien, SQL, Plugins), kritisch (PHP-Code, WP-CLI, PHP-Dateien, .htaccess, mu-plugins).
  • Die Begründung von Claude.
  • Genau, was passiert: Vorher/Nachher-Vergleich, vollständiger Code, SQL-Anweisung oder Befehl.

Sammelfreigabe

Unter Claude MCP → Freigaben stehen alle offenen Vorschläge mit Kästchen. Markieren (oder „Alle auswählen“), einmal bestätigen, „Markierte freigeben“ – fertig. So lässt sich z. B. eine neue Plugin-Version mit mehreren Dateien in einem Schritt freigeben.

  • Bestätigt wird nach dem höchsten Risiko der Auswahl (ein Code bzw. Passwort + Code).
  • Reihenfolge: älteste zuerst, Plugin-Hauptdateien zuletzt (in der Liste markiert) – die neue Versionsnummer greift erst, wenn alle anderen Dateien geschrieben sind.
  • Schlägt ein Vorschlag fehl, wird angehalten; der Rest bleibt offen. Darüber erscheint ein Ergebnisblock.
  • Vorher jeden Vorschlag über „ansehen“ prüfen – die Sammelfreigabe ersetzt nicht die Kontrolle.

Weitere Regeln:

  • Nur der Administrator, der Claude verbunden hat, kann seine Vorschläge entscheiden.
  • Wurde ein Beitrag oder eine Datei nach dem Vorschlag verändert, wird die Freigabe abgelehnt statt überschrieben.
  • Nach 5 Fehlversuchen (Passwort oder Code) sind Freigaben 15 Minuten gesperrt.
  • Dateiänderungen haben einen „Rückgängig machen“-Knopf (stellt den vorherigen Stand wieder her, solange die Datei seitdem nicht erneut geändert wurde).
  • Datenbank- und WP-CLI-Änderungen lassen sich nicht automatisch zurücknehmen – vor großen Änderungen ein Backup anlegen.

5. Zwei-Faktor mit Aegis

Zusätzlich zum Passwort kannst du riskante Freigaben mit einem 6-stelligen Code aus Aegis Authenticator (oder jeder anderen TOTP-App) absichern. Das gilt nur für Freigaben dieser Bridge und ist unabhängig vom Zwei-Faktor beim WordPress-Login.

Einrichten

  1. Claude MCP → Einstellungen → Zwei-Faktor-Bestätigung: Passwort eingeben, Einrichtung starten.
  2. Auf dem Handy „In Authenticator-App öffnen“ antippen – Aegis übernimmt den Eintrag direkt. Alternativ in Aegis „+ → Manuell eingeben“ mit dem angezeigten Schlüssel (TOTP, SHA1, 6 Stellen, 30 Sekunden).
  3. Den aktuellen Code aus Aegis eintragen und Aktivieren.
  4. Die 10 Backup-Codes sicher aufbewahren (z. B. im Passwortmanager). Jeder funktioniert einmal, falls das Handy fehlt. Sie werden nur einmal angezeigt.

Wo der Code abgefragt wird

  • Freigaben mit Risiko „hoch“ oder „kritisch“ (Dateien, SQL, Plugins, PHP, WP-CLI) – zusammen mit dem Passwort oder, mit der Option „Freigaben nur mit Zwei-Faktor-Code“, allein.
  • „Rückgängig machen“ bei Dateiänderungen.
  • Einschalten des Expertenmodus und Ändern der WP-CLI-Pfade.
  • Optional auch bei normalen Inhaltsfreigaben (Einstellung „Code auch für normale Inhaltsfreigaben verlangen“).

Richtlinie

  • Erzwingen: Riskante Freigaben sind nur noch mit eingerichtetem Zwei-Faktor möglich. Wer keinen eingerichtet hat, kann sie nicht freigeben.
  • Freigaben nur mit Zwei-Faktor-Code (ab 0.4.0): Bei Freigaben entfällt das WordPress-Passwort, der Code ist dann Pflicht. Rückgängig, Expertenmodus und diese Einstellungen verlangen weiterhin Passwort und Code. Ohne eingerichteten Zwei-Faktor gilt automatisch wieder das Passwort. Wichtig: Backup-Codes sicher aufbewahren und Aegis-Sicherung aktivieren.
  • Richtlinie ändern, neue Backup-Codes erzeugen oder Zwei-Faktor deaktivieren geht nur mit Passwort und gültigem Code (oder Backup-Code).

Technik

  • TOTP nach RFC 6238. Der Schlüssel wird verschlüsselt gespeichert (libsodium, Schlüssel aus den WordPress-Salts).
  • Jeder Code gilt nur einmal (Replay-Schutz), ±30 Sekunden Toleranz für die Handy-Uhr.
  • Backup-Codes nur als Hash gespeichert.

Handy verloren?

Mit einem Backup-Code anmelden, Zwei-Faktor deaktivieren und neu einrichten. Ohne Backup-Codes: per WP-CLI auf dem Server wp user meta delete <ID> _cmb_totp_secret und wp user meta delete <ID> _cmb_totp_backup ausführen (bzw. über den Hoster).

6. Expertenmodus

Unter Einstellungen → Expertenmodus lassen sich fünf Bereiche einzeln einschalten. Zum Einschalten ist dein Passwort nötig. Danach den Connector in Claude einmal trennen und neu verbinden, damit Claude die zusätzliche Berechtigung erhält.

Immer gesperrt – auch mit Freigabe

  • Lesen oder Ändern von Zugangsdaten: wp-config.php, .env, .htpasswd, Schlüssel/Zertifikate, Datenbank-Dumps und Backup-Ordner.
  • Ändern von WordPress-Core (wp-admin, wp-includes, wp-*.php) und PHP-Dateien im Upload-Ordner.
  • Alles, was die Claude MCP Bridge selbst betrifft (Plugin-Ordner, eigene Tabellen, Deaktivieren/Löschen über Claude) – damit kein Vorschlag die Freigabepflicht aushebeln kann.
  • SQL: Benutzer-/Rechteverwaltung (GRANT, CREATE USER …), Dateizugriff (INTO OUTFILE, LOAD_FILE), Stored Procedures/Trigger/Events, mehrere Anweisungen auf einmal.
  • WP-CLI: shell, server, db export/import/query/cli, config get, --ssh, --http, --path, --require, --exec. Befehle laufen ohne Shell – Pipes, ;, $(…) haben keine Wirkung.

WP-CLI einrichten

WP-CLI muss auf dem Server installiert sein und PHP muss proc_open erlauben (bei vielen Shared-Hostern nicht der Fall). Trage den Pfad zu wp ein (z. B. /usr/local/bin/wp). Bei einer .phar-Datei ohne Shebang zusätzlich den Pfad zum PHP-CLI (z. B. /usr/bin/php).

Komplett abschalten

In wp-config.php: define( 'CMB_DISABLE_POWER_TOOLS', true ); – sperrt den Expertenmodus unabhängig von den Einstellungen. Außerdem werden DISALLOW_FILE_MODS und DISALLOW_FILE_EDIT respektiert.

8. Sicherheitsmodell

Verbindung

  • OAuth 2.1, nur Authorization Code mit PKCE (S256). Weiterleitung ausschließlich an https://claude.ai/api/mcp/auth_callback (Claude Code/Loopback nur per Opt-in).
  • Registrierung neuer Clients nur im Kopplungsfenster, max. 20 Clients, Rate-Limits.
  • Zustimmung nur durch eingeloggte Administratoren, mit Nonce und Klickjacking-Schutz.
  • Codes: 2 Minuten, einmalig. Access-Token: 1 Stunde. Refresh-Token: 30 Tage, wird bei jeder Nutzung ersetzt; Wiederverwendung sperrt die ganze Verbindung.
  • Tokens sind an die Connector-URL gebunden, werden nur gehasht gespeichert und nur im Authorization-Header akzeptiert.
  • Der Token gilt nur für den MCP-Endpunkt – nicht für die übrige WordPress-REST-API.
  • Expertenmodus nur mit eigener Berechtigung wp:power, die bei der Zustimmung deutlich angezeigt wird.

Ausführung

  • Ohne Freigabe laufen nur lesende Operationen. Lesende SQL-Abfragen laufen zusätzlich in einer READ-ONLY-Transaktion (MySQL/MariaDB).
  • Freigabe: eingeloggt + Nonce + Capability + bei Risiko „hoch/kritisch“ Passwort und – wenn eingerichtet bzw. erzwungen – TOTP-Code. Doppelte Ausführung ausgeschlossen, Integritäts-Hash pro Vorschlag.
  • Bei der Ausführung wird alles erneut geprüft (Rechte, Sperrlisten, Veraltung, ob der Bereich noch eingeschaltet ist).
  • Beitragsinhalte werden immer durch wp_kses_post gefiltert – auch für Admins –, damit eingeschleustes <script> (z. B. über einen Kommentar, den Claude gelesen hat) nicht auf die Website gelangt.
  • Datei-Pfade werden auf die WordPress-Installation begrenzt (keine .., keine Symlink-Ausbrüche). PHP-Dateien werden vor dem Speichern auf Syntaxfehler geprüft.
  • Geheimnisse werden geschwärzt, bevor eine Antwort an Claude geht: Passwort-Hashes, Sitzungen, API-Schlüssel und Webhook-Secrets – auch innerhalb serialisierter Plugin-Einstellungen – sowie bekannte Schlüsselformate in Dateien und Ausgaben. Das schützt vor versehentlicher Ausgabe, nicht vor gezielten Teilabfragen per SQL.
  • Protokoll aller Verbindungen, Tool-Aufrufe und Entscheidungen unter Claude MCP → Protokoll (IPs gekürzt, 90 Tage).

Wichtig zu wissen

Mit freigegebenem PHP-Code, PHP-Dateien, WP-CLI oder SQL kann alles auf dieser Website verändert werden. Die Sperrlisten (z. B. Bridge-Dateien, wp-config.php) schützen vor versehentlichen oder untergeschobenen Vorschlägen, aber der eigentliche Schutz ist deine Prüfung vor dem Freigeben. Gib nichts frei, was du nicht verstehst – besonders, wenn Claude vorher Kommentare, Formulareingaben oder fremde Inhalte gelesen hat.

9. Notfall & Widerruf

  • Claude MCP → Verbindungen: einzelne Verbindung trennen oder Alle Verbindungen trennen.
  • Bridge deaktivieren (Einstellungen) oder Plugin deaktivieren: alle Tokens werden sofort ungültig.
  • Passwort- oder Rollenänderung des Admins macht dessen Tokens automatisch ungültig.
  • define( 'CMB_DISABLE_POWER_TOOLS', true ); in wp-config.php sperrt den Expertenmodus sofort.

10. Fehlerbehebung

Claude meldet „Couldn't reach the MCP server“
Prüfe HTTPS, Permalinks und dass „Bridge aktiv“ gesetzt ist. Sicherheits-Plugins oder Firewalls (WAF) dürfen /wp-json/cmb/v1/ und /.well-known/ nicht blockieren.
„Registration is closed“
Vor dem Verbinden in WordPress „Kopplung starten“ klicken.
„Unauthorized“, obwohl verbunden
Manche Apache/CGI-Hoster entfernen den Authorization-Header. In die .htaccess oberhalb des WordPress-Blocks: SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1
Aegis-Code wird abgelehnt
Uhrzeit des Handys auf „automatisch“ stellen. Jeder Code gilt nur einmal – nach einer Freigabe auf den nächsten Code warten. Tipp: mehrere Vorschläge per Sammelfreigabe mit einem Code freigeben.
Expertenmodus-Tools fehlen in Claude
Nach dem Einschalten den Connector in Claude trennen und neu verbinden.
WP-CLI „nicht verfügbar“
Pfad prüfen; viele Hoster deaktivieren proc_open. Dann den Bereich ausgeschaltet lassen.
Plugin-Installation schlägt fehl
Der Server muss wordpress.org erreichen und schreiben dürfen (FS_METHOD „direct“). Andernfalls über das normale WordPress-Backend installieren.
